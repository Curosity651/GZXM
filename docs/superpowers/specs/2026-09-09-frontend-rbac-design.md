# GZXM 前端 RBAC 改造设计

## 目标

将当前依赖固定角色名称的前端权限判断改为可配置 RBAC，用于快速验证角色、菜单、操作按钮与课题数据范围的关系。所有数据继续保存在 Zustand 和 localStorage 中，不引入后端接口。

规则预警功能保持现状，不删除菜单、页面、Mock 数据或计算逻辑。

## 数据模型

### 用户

每个账号只绑定一个角色，新增以下字段：

- `roleId`：关联角色。
- `dataScope`：`ALL` 或 `TOPICS`。
- `topicIds`：数据范围为 `TOPICS` 时允许访问的一个或多个课题。

角色只决定账号能做什么，数据范围只决定账号能看到哪些课题。业务代码不再通过“课题牵头单位”等角色名称推断数据范围。

### 角色

角色包含：ID、名称、编码、说明、启用状态、是否内置、权限编码列表。现有四个身份迁移为初始角色：

- 系统管理员
- 项目技术负责人
- 科研助理
- 课题牵头单位

系统管理员是内置超级角色，始终拥有全部权限，不能编辑、停用或删除。

### 权限

权限目录分为两类：

- 菜单权限：控制左侧菜单和路由访问。
- 操作权限：控制新增、编辑、提交、初审、终审等业务按钮。

权限使用稳定编码，例如 `achievement.entry.view`、`achievement.submit`、`achievement.initial.approve` 和 `achievement.final.approve`。

## 权限解析

登录后通过用户的 `roleId` 获取角色。菜单构建、路由守卫和业务按钮均查询同一份角色权限列表。角色被停用时，其关联账号不能登录。系统管理员直接取得完整权限目录。

课题相关列表通过用户的 `dataScope` 和 `topicIds` 过滤：`ALL` 返回全部课题数据，`TOPICS` 只返回被授权课题的数据。

## 管理页面

### 用户管理

保留新增、编辑、启用/停用和重置密码功能。账号表单改为选择动态角色，并配置“全部课题”或“指定课题”。指定课题时支持选择一个或多个课题。

### 角色权限管理

系统管理下新增角色权限管理页面，支持：

- 新增和编辑角色；
- 启用或停用非内置角色；
- 按业务模块配置菜单权限和操作权限；
- 查看每个角色关联的账号数量；
- 删除没有关联账号的非内置角色。

已关联账号的角色不能删除，只能停用。内置系统管理员只读展示。

## 初始兼容策略

Mock 数据初始化时创建四个初始角色，并将现有用户映射到对应 `roleId`。旧 localStorage 数据无法满足新结构时，使用新的持久化版本重新加载 Mock 数据，避免复杂迁移影响原型验证。

## 范围边界

- 保留规则预警全部现有功能。
- 不实现字段级权限。
- 不实现一个账号绑定多个角色。
- 不实现后端鉴权或安全防护；前端 RBAC 仅用于原型交互验证。
- 不新增或运行自动化测试。

## 验证方式

实现后只执行 TypeScript/Vite 生产构建，并在浏览器中手动检查：

1. 内置系统管理员可访问全部页面且不能被修改。
2. 新建角色可配置菜单和操作权限。
3. 用户绑定角色后菜单与按钮随权限变化。
4. 用户的数据范围可切换为全部课题或指定多个课题。
5. 规则预警菜单及页面仍可正常访问。
