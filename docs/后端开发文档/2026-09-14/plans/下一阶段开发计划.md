# 下一阶段开发计划

## 1. 总原则

下一阶段仍以本地开发为主，不立即部署阿里云。先稳定开发环境、MySQL 技术基线和 API 契约，再创建数据表和业务模块。

每项工作必须独立建任务，写明负责人、允许修改路径、禁止修改路径、验收标准和测试命令。协作开发遵守根目录 `AGENTS.md` 及 `docs/collaboration/`。

## 2. 推荐顺序

### 阶段 A：统一可运行环境

负责人：A。

目标：让四位成员得到一致工具链，但仍不创建业务表。

- 确定 JDK、Maven Wrapper、Node.js、npm、Docker 和 MySQL 版本。
- 提供版本检查与本地启动说明。
- 统一使用 npm，避免 npm/pnpm 混用。
- 更新 `.env.example`，只保留安全的本地示例值。
- 修正 README 中遗留的 PostgreSQL 说明。

退出条件：四台开发机都能启动 MySQL 容器、前端和一个不依赖业务表的后端健康检查。

### 阶段 B：完成 MySQL 依赖切换

负责人：A；审查人：B。

- 将 PostgreSQL JDBC 驱动替换为 MySQL Connector/J。
- 将 Flyway 数据库支持切换为 MySQL。
- 保留自动建表关闭。
- 隔离或移除 PostgreSQL 测试模式依赖，但不直接生成正式业务表。
- 为 MySQL 连接增加最小启动测试。

退出条件：后端能连接空 MySQL，健康检查正常，并且不会自动创建表或初始化账号。

### 阶段 C：冻结 API v1 契约

负责人：A 协调，B/C/D 分别负责自己的模块。

- 创建 `docs/api/openapi.yaml`。
- 统一成功/错误响应、分页、日期时间、ID、状态枚举和错误码。
- 定义所有模块的接口路径和权限要求。
- 先定义契约，不要求同时实现 Controller。
- 前端根据契约建立 HTTP client 和 Mock API adapter。

退出条件：四人完成接口评审，跨模块依赖、请求响应和权限边界不存在未决歧义。

### 阶段 D：设计第一批基础数据表

负责人：A；B 参与项目主数据；其他成员审查依赖字段。

第一批只包含：

- 用户、角色、页面权限、操作权限。
- 项目、课题、单位和课题—单位关系。
- 必要的审计字段。
- 文件元数据的最小公共契约，可先不实现真实上传。

先输出数据字典和关系图，评审通过后再生成第一版 MySQL Flyway 迁移。不得直接把现有 PostgreSQL V1 当作 MySQL 迁移使用。

退出条件：空库迁移通过、约束有测试、登录和项目查询可在 MySQL 真实运行。

### 阶段 E：前端接入基础 API

负责人：A 负责认证，B 负责项目主数据。

- 建立统一 HTTP client。
- 接入登录、当前用户、项目、单位和课题查询。
- 统一处理 JWT、401、403、网络错误和 loading。
- 移除对应功能对 Mock 登录和 Mock 项目数据的依赖。

退出条件：浏览器登录后能从 MySQL 查询实际项目和课题，刷新页面后登录状态处理正确。

### 阶段 F：分模块并行开发

在基础契约稳定后开始：

- B：指标、分配，然后监测预警。
- C：成果五类型、材料和审批。
- D：报告、归档和文件服务。
- A：权限、公共集成、迁移审核和 CI。

依赖顺序：

```text
项目/课题/单位
  ├── 指标定义与分配 ──┐
  ├── 文件服务 ────────┼── 成果
  ├── 报告 ────────────┤
  └── 归档 ────────────┘
                         ↓
                    监测预警
```

### 阶段 G：集成与测试环境

- 全量权限、状态机、事务和 API 测试。
- 准备脱敏测试数据。
- 执行备份恢复和迁移演练。
- 完成日志、监控和安全配置。
- 在测试环境验收，不直接进入生产。

### 阶段 H：阿里云部署

本地和测试环境验收完成后才开始：

- RDS MySQL、OSS、应用运行环境和网络规划。
- 环境变量与密钥管理。
- HTTPS、域名、备份、告警和回滚。
- 上线检查和用户验收。

## 3. 下一步最合适的三个任务

1. `基础环境任务`：安装并统一 JDK、Node.js/npm 和 Docker，修正运行文档。
2. `MySQL 驱动任务`：只切换依赖并验证连接空库，继续禁止自动建表。
3. `API 契约任务`：创建完整 OpenAPI v1 文档，不创建业务表。

建议按 1 → 2 → 3 执行。完成 API 契约评审后，再启动数据字典和 MySQL 表设计。

## 4. 本阶段禁止事项

- 不直接部署阿里云。
- 不让四个人同时修改基础框架。
- 不根据前端 Mock 类型自动生成所有数据库表。
- 不在 API 契约未评审前批量实现 Controller。
- 不继续使用 PostgreSQL 专用迁移创建 MySQL 表。
- 不提交本地密钥、真实用户数据或 `node_modules`。
