# GZXM 重点项目科研管理系统（前端 Mock 原型）

本项目是面向一个固定重点项目的前端业务原型。重点项目下包含多个课题，科研指标、成果和月季报按课题办理；每个课题还可在归档模块中新建多个配套自筹项目。

## 本期能力

- RBAC 角色权限：可新增、编辑、停用和删除自定义角色，并分别配置页面权限与业务操作权限；
- 用户账号只绑定一个角色和一个所属单位，单位账号的数据范围由课题成员关系自动推导；
- 系统管理员为内置保护角色，可查看全部页面并负责系统配置，默认不参与业务审批；
- 科研助理可新增课题、选择牵头单位，维护五类预置及自定义指标并直接下发课题指标；
- 课题牵头单位可添加承担单位，再将课题指标分配给牵头单位和各承担单位；分配合计不得低于课题目标；
- 成果管理采用“重点项目—课题—成果类型”树形结构，并按课题和单位控制数据范围；
- 论文、专利、软著、标准采用投稿/申请前预审，预审通过后登记实际投稿/申请，再补充正式材料并完成两级审批；
- 每项成果使用同一条记录贯穿完整生命周期，只有正式终审后“已生效”的成果计入指标；
- 人才培养直接进入正式成果两级审批；
- 课题月报、季报六项模板、逾期标记及两级审批；
- 重点项目公共材料、课题国家材料、配套自筹项目三类归档；
- 科技项目、技改项目、基建项目归档清单；
- Mock 文件信息、审批记录、本地持久化和一键重置。

## 运行

```bash
npm install
npm run dev
```

默认开发地址由 Vite 输出。本地预览构建：

```bash
npm run build
npm run preview
```

## 数据说明

- 数据保存在浏览器 `localStorage`，key 为 `gzxm-research-management-v3`；
- “重置演示数据”会恢复内置课题、指标、成果、报告和归档示例；
- 上传文件只记录名称、数量和 Mock 标识，不保存到真实文件服务器；
- 前端 RBAC、用户与数据权限仅用于原型演示；生产环境仍需由后端接口强制校验权限和数据范围。
